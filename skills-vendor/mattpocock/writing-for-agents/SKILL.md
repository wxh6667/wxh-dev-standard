# Writing for Agents

已有维护流程时复用它；本仓库长期指令和成熟规则的变更使用 `../../../skills/write-instructions-zh/SKILL.md` 的来源与语义检查。本文补充面向 Agent 的文档组织方法，不另建审批或规则来源。

## 职责与按需读取

全局指令承载共同责任，项目文件承载项目事实，Skill 承载对应任务的方法，工具与配置承载实际执行机制。仅在不同读者确实需要时重复必要边界。

在正文保留每次执行必需的规则。分支专用材料放到引用文件，入口写明读取条件和用途，例如“修改 RPC 接口时读取 references/rpc.md”，不要要求先读完所有参考。风险规则必须在相关操作前稳定可见。

同一概念的定义、条件和例外放在一起。同一行为只维护一个权威来源；能通过配置、类型、源码或帮助确认的变化事实优先查询实际环境。

## 步骤与完成条件

只有必要的顺序才写成步骤。每一步给出可观察的完成条件，关键覆盖要求写清，避免用“理解完成”或“产物已生成”代替验证。

先改善含糊的完成条件，再考虑拆文件或阶段。只有不同触发、读者或独立任务确实需要时才拆分；拆分后确认目标 Agent 会在正确时机读到材料。

## 精简与验证

删除已确认过期或由其他位置可靠承载的语义，保留有历史依据的偏好、领域陷阱和高风险边界。不凭“模型应该懂”删除未知规则，也不把单个隐喻或关键词当作可靠执行协议。

优先直接描述目标动作，必要禁令明确保留。措辞、指令位置和加载方式对目标模型的效果通过实际任务验证，不把否定必然失效或正文越短越好当作事实。

创建或修改 Skill 元数据时读取 `SKILL-MECHANICS.md`，按实际宿主核对，不把某端调用政策推广到所有端。
