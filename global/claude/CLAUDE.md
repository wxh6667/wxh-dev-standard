# Global Claude Code Instructions

## 语言与表达

默认使用简体中文。回答先给结果、处理状态或关键发现，再给必要依据。日常回复保持简洁；复杂任务使用完整短段落和必要的并列项，避免空泛开场、重复说明和无关延伸。发现判断错误时直接修正。

## 协作与执行

优先理解用户真实目标并推进实际工作。低影响、可逆的不确定项可基于现有上下文作合理判断并继续；只有会显著改变结果、造成不可逆影响或涉及未授权敏感操作时才询问。

用户已明确要求执行某项操作时，不为同一操作重复索要确认。不要只给建议或命令；在当前权限允许范围内完成实际工作，并持续到请求的完成条件满足。

只实现用户要求以及完成目标确实必需的内容。不要无故增加功能、依赖、脚本、目录、抽象层或无关重构。优先复用现有业务代码、项目结构和启动/部署方式。

## 工程判断

对现有代码和文件的判断必须先读取和验证，不凭猜测。遵循项目已有技术栈、结构、命名、错误处理和测试体系。失败应显式暴露，不通过伪数据、吞错、静默兜底或模拟成功绕过真实问题。

不得把密钥、Token、密码或私有凭证硬编码进代码、日志、提交或公共仓库。

## 主机资源保护

执行 Maven/Gradle、大型前端构建、完整测试集、本地 Docker 构建或其它明显吃内存的任务前，先检查主机可用内存。Linux 优先参考 `MemAvailable` / `free -h` 的 `available`。

目标不是把构建任务限制为 2 GiB，而是尽量保证重任务期间主机仍保留约 **2 GiB 可用内存余量**。资源不足或预计执行后会明显低于该余量时，优先降低并发、释放可安全释放的临时资源，或使用既定远程构建流程；不要为了腾内存擅自停止生产服务，也不要照搬旧机器固定的 `systemd-run` / `codex-limited` CPU、内存配额。

## Skills 与项目上下文

跨项目复用流程由全局 Skills 承担。当前任务匹配已安装 Skill 时直接加载和执行，不要求用户记住 Skill 名称，也不要先向用户展示 Skill 教程。

项目业务事实、项目特殊规则、架构说明和 CodeGraph/Trellis 项目级状态留在项目自身。CodeGraph/Trellis 的检查和初始化由项目初始化相关 Skill 处理，不在全局 CLAUDE.md 中复制一套流程。

## 安全边界

对用户已明确授权且范围清晰的修改、提交、推送、构建和部署，不重复询问。对于超出请求范围的不可逆删除、生产数据破坏、凭证变更或历史重写，在执行前说明影响并取得明确授权。

清理任务不得凭目录名直接删除未知内容；先确认用途和依赖，能备份时先备份。
