# App Shell UI

先检查现有路由、品牌、tokens、主题、组件和依赖。局部修改保留既有设计；以下默认值用于新设计或已授权的重设计，不覆盖项目已有主题、布局和交互。

## 选择页面类型

- **App Mode**：登录后的工具、设置、控制台、聊天与工作台，采用导航与任务内容区。
- **Website Mode**：官网、落地页、作品集、阅读、目录与文档，按访客目标设计页面结构，使用正常页面滚动。

同时存在两种页面时分别设计，可以共享品牌 tokens。仅在两种合理选择会显著改变结果且上下文无法决定时询问。

## App Mode

按任务选择设置型、控制台型、工作台型或三栏布局，读取 `references/layouts.md` 的相应配方。单一品牌主色、柔和画布、逐级抬升的表面、清晰的文字层级和细边框形成克制的工具界面。

默认侧栏宽 220–260px，图标栏 48–56px，内容间距 20–28px，间距按 4px 网格组织，圆角采用 8/12/16/999。允许根据内容和既有系统调整。内容以文字、统一描边图标与状态标签为主，装饰只用于有目的的重点或空状态，不铺满卡片与列表。

新设计默认提供浅色与深色，用户明确选择单主题时遵从。已有项目沿用现有主题及切换机制，不为局部修复添加主题功能。需要新主题时读取 `references/tokens.md`，用 CSS 变量承载表面、文字和控件颜色；新切换器可使用根元素 `data-theme` 并保存偏好，不用颜色反转模拟深色。

以目标桌面视口（通常 1280×800）规划主要任务，尽量一屏完成；内容较长时采用合理滚动或渐进展示，不为了首屏强制拆路由、隐藏控件或缩小文字。并排且属于同一组的面板保持视觉对齐，长列表可用有明确高度的内部滚动区。移动端优先保证主要操作可达。

实现组件时读取 `references/components.md`。导航、选择、表单、过滤、开关与发送操作应真实工作，按需要提供加载、空、错误、禁用和成功状态。动效用于反馈，颜色/背景通常 150–200ms，遵守减少动态效果偏好。

## Website Mode

实施前读取 `references/web-frontend.md`，结合品牌和访客目标选择说服、阅读、体验或目录结构。确定调色、文字角色、图片处理和一个服务于内容的视觉重点，避免每个页面都套相同 hero 与卡片模板。

使用正常页面滚动，不继承 App Mode 的固定画布和人工窗口外壳。主题由品牌与产品需求决定，不自动要求双主题。沿用语义 tokens，通常不超过两个文字字体系列，必要时另用代码字体。

采用用户提供的事实、真实产品状态和有权使用或生成的图片。未知指标、客户、评价、Logo 和截图明确标为占位或省略，不编造商业证据或假界面。

## 按需使用 Top 50 组件

请求需要具体组件交互或完整画廊时，先读 `references/top50-components.md`，只选择必要组件。

复制 `assets/top50-react/components/items/` 中对应文件时，保持 `components/items/`、`components/shared.tsx` 与项目根 `lib/cn.ts` 的相对布局；额外包一层目录会破坏导入。按实际使用复制共享文件，样式映射到当前页面 tokens，业务文案和样例数据替换为实际内容。

完整画廊使用 `components/top50-gallery.tsx` 与 `data/top50.ts`，一次展示选中组件，其他组件通过导航访问。组件是交互参考，不能引入第二套页面外壳，也不作为公共网站的默认视觉风格。

需要更新资产时运行 `python scripts/sync_top50_assets.py --source /path/to/top50`。来源及选择记录见 `references/top50-components.md` 与资产包，不依赖维护者本机路径。

## 验收

检查实际渲染、业务交互、键盘操作、焦点、语义标签、对比度、图片尺寸预留、内容极值及空/错误状态。检查桌面和相关移动断点（320/375/414/768px），没有水平溢出、遮挡、不可达操作或仅悬停可用的功能。

验证所有实际支持的主题，确认控件和次要文字可读、选中状态清晰。首屏体现主要任务或网站主张与行动入口，长内容仍可访问。页面滚动、主题数量与布局以本次目标和既有系统为准；参考文件中的默认配方不扩大修改范围。
