# Host Resource Guard

这是跨机器通用的重任务资源保护规则，不绑定某一台旧主机，也不固定某个 cgroup、builder 或 CPU 配额。

## 核心要求

执行 Maven/Gradle、大型前端构建、本地测试集、Docker 构建或其它明显吃内存的任务前，先检查主机当前可用内存。Linux 优先参考 `/proc/meminfo` 中的 `MemAvailable` 或 `free -h` 的 `available`，不要只看 `free` 字段。

默认目标是：**给主机至少保留约 2 GiB 的可用内存余量**。

这不是“给构建任务限制为 2 GiB”，而是保护操作系统、Agent、SSH、数据库和其它常驻服务不要因为构建把内存吃光。

如果当前可用内存已经接近或低于 2 GiB，或者根据当前服务占用/构建规模判断启动重任务后很可能把可用内存压到 2 GiB 以下：

1. 不要直接启动高内存构建；
2. 先确认是否有可以安全停止或清理的临时进程/缓存；
3. 能降低 Maven/Gradle/测试并发时优先降低并发；
4. 生产 Docker 镜像按本仓库规则优先走 CNB 远程构建，本地不要为了绕过资源不足去构建生产镜像；
5. 不要擅自停止数据库、生产容器或其它业务服务来“腾内存”；
6. 无法在不影响业务的情况下保留约 2 GiB 余量时，明确报告资源不足，而不是强行执行导致 OOM。

## 不再默认使用的旧策略

旧环境中的 `systemd-run` 固定 2 CPU / 2 GiB、`codex-limited` Docker builder 固定 3 GiB / 2 CPU 等只是当时的实现手段，不是当前标准。

除非当前机器确实需要且经过实际测量，否则不要为了复刻旧机器而创建固定 cgroup、固定 builder 或硬编码 CPU/内存上限。
