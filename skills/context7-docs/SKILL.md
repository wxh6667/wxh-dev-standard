# 库文档查询

## 何时查

下列情况默认先查，不等到出错或不确定：

- 写或修改调用第三方库、框架、SDK、云服务 API、CLI 的代码或命令，哪怕是常见的 API。
- 回答某个库的参数、配置项、默认值、安装与初始化方式、推荐写法。
- 版本升级、迁移、弃用、破坏性变更，或同一库的大版本行为差异。
- 报错栈或日志指向某个库，需要确认是用法错误、版本不匹配还是已知行为。
- 用户提到的库名、函数名或配置你无法立刻确认其当前存在且签名正确。

不查：纯业务逻辑、读本地代码就能回答的问题、与具体库无关的编程概念，以及同一对话里已取得且仍适用的同版本文档。

## 查询方法

1. 先从 `package.json`、`pom.xml`、`go.mod`、`pyproject.toml`、锁文件或用户信息确定目标版本。
2. 已有专业文档工具或 Skill 能取得目标版本的一手资料时直接使用，不重复查询。OpenAI 产品优先用官方文档工具；Claude / Anthropic 问题有可用官方能力时用它。
3. 用 Context7 时先 `resolve-library-id` 确认库，再 `query-docs` 查具体主题。名称有歧义时带上生态和版本；用户或项目给出了 `/org/project/version` 形式的 ID 时可跳过 resolve。已知编程语言时传 `language`。
4. 每次 query 只问一个具体概念，写成完整问题（如“Next.js 15 middleware 如何按路径匹配”），不要写“auth”“hooks”这类宽泛词，也不要把多个主题塞进一次查询。同一问题最多查 3 次，仍不足就换来源。
5. 结果与项目版本或其他一手材料冲突时，核对版本及原始出处。无法确定时说明冲突，不猜测。
6. 查不到或查询失败时使用官方文档站、已安装的类型定义或源码，必要时搜索官方资料；明确说明失败或覆盖缺口。

引用 API 行为时说明适用版本。Context7 是文档检索通道，事实以对应版本的官方文档、类型和源码为准。项目内部事实用本地工具确认，离线任务遵守用户资料范围。已经取得足够、适用的证据时停止检索。不要把查询内容写入 API Key、口令或专有源码。
