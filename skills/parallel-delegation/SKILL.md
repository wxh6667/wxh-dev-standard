# 并行委派

目标是把一批彼此独立或部分相依的工作单元做完，同时保证写冲突、半成品和未验证结果不混进交付。并发只发生在互斥写域和依赖已满足的单元之间，合并与最终验收回到主 Agent。

## 开闸判断

满足任一条才用：单元 ≥2 且至少两个能同时推进；单个单元会产生大段中间输出，需要隔离上下文；用户明确要求并行或分域。

纯串行链（A 完才做 B）不是并行任务，按顺序做完即可；同层永远只有一个就绪单元的树，编排成本高于收益。

## 任务树

把批次写成有向无环图：节点是 unit，边是「前者的产出是后者的输入」。

```
u1  DEPENDS: []        改解析层
u2  DEPENDS: []        改存储层
u3  DEPENDS: [u1]      接入新解析结果
u4  DEPENDS: [u1,u2]   端到端用例
```

- 每个 unit 显式写 `DEPENDS`，空表示开局可派。
- 边必须能说出传递物：接口签名、生成物、数据格式或已合并的提交。说不出传递物就不是依赖，删掉这条边，否则会把本可并发的活人为串起来。
- 存在环，或同一写域在依赖链上反复出现，回到拆分，不强行排期。

## 并发与串行

只有三种情况串行，其余同层并发：

1. **依赖未满足**：下游需要上游的接口或产物。
2. **写域重叠**：两个 unit 的路径有交集 → 合并成一个 unit，或改成显式依赖，绝不同层并发。
3. **共享全局文件**：lockfile、迁移、生成代码、公共导出桶。设一条串行车道，指定唯一 owner，或在全部单元完成后由末尾的集成单元统一改；任何与之并发的 unit 都算预检失败。

层内并发、层间串行。同一层在一条消息里派完，等整层返回再释放下一层，不边跑边放。

## 派发前预检

不过就零成本退出，改分域或收窄批次后重做：

- 每个 unit 实际列出写路径（`git ls-files`、glob 或目录树），不是凭 brief 文字声称；两两求交集必须为空。
- lockfile、入口文件、公共类型与共享配置归属唯一 unit，或列入禁改。
- 依赖无环，且每条边都有可指名的传递物。
- 所有路径都在当前仓库内。
- 主工作区干净，或已把 `worktree.baseRef` 设为 `head`。worktree 默认从 `origin/<默认分支>` 建，未提交改动和未推送提交不在其中；基线不一致时派出去也白跑。

## brief

每次派发带完整 brief，不依赖上一轮会话记忆：

```
GOAL       一句话结果，没有会话上下文也能执行
SCOPE      允许写的路径；禁止写的路径（派发前已实际核对）
DEPENDS    已完成的上游 unit、其契约要点、已合并的 head
CONTEXT    文件指针与上游产物路径
ACCEPTANCE 逐条可检查的判据
VERIFY     确切命令与已知坑
TIMEBOX    运行上限，到期返回已有结论
FORBIDDEN  禁 rebase、禁强推、禁越域修复；单元专属禁令
REPORT     status / worktree 路径与分支 / head_sha / verdict / 改动文件 / 实际跑过的命令与输出路径 / 偏差
```

小任务压缩成一段话，但仍要含 goal、scope、depends、verify、report。指令跨轮次会衰减，返修也要重新给出全量 brief。

## 隔离与派发

写入型子代理必须各自持有隔离工作区。Claude Code 用 Agent 的 `isolation: "worktree"`；宿主不提供隔离能力时写任务串行，只读侦察与检索仍可并行。

同会话并发子代理上限为 20，超限会被拒绝且不应重试；就绪单元多于上限时分轮。worker 不 rebase、不强推、不碰他人分支。

无改动时宿主自动清理 worktree，有改动时保留并回传路径与分支，分支名由宿主生成而非 brief 指定。worktree 子代理的项目指令来自主会话，不读工作树根上可能不同的 `CLAUDE.md` 与 `.claude/rules/`。

只读侦察用只读子代理类型（Claude 的 `Explore`），或派通用子代理并在 brief 中明确禁止写入。子代理默认可再派生，深度上限 3 层；本流程保持单层，不让 worker 再派 worker。

## 调度循环

1. 取入度为 0 的 ready 集合；超过 20 个就截断分轮。
2. 一条消息派发全部 ready，brief 带上游契约。
3. 等整层结束。后台结果以完成通知到达，不轮询、不逐个追问进度。
4. 按依赖顺序串行合并本层，每合一个重跑该 unit 的 VERIFY。
5. 合并成功的 unit 从图上移除，其下游入度减一，减到 0 的进入下一轮 ready；失败的 unit 记 failed，其依赖方记 blocked，整条下游不派发。
6. ready 为空而仍有 pending：出现环或失败传播，停止并报告卡点。

与失败单元无关的分支继续推进，不因一个节点堵死整棵树。

## 汇合只认副作用

判定完成只看 worktree 分支、head_sha、改动文件和验收命令输出。子代理的文字结论、会话记忆和「看起来没问题」都不算证据；只活在报告里的工作等于没做。

## 合并

宿主不提供自动合并：拿到 worktree 路径与分支后，由主 Agent 在主检出里按拓扑顺序串行合并，一次一个；同层合并顺序按 unit id 固定，减少随机性。

合并冲突说明预检遗漏或契约被违反：退回新 worker，brief 带上已合并的 base、冲突文件与双方改动，不在旧会话上追加指令。

分支保留到复核通过再清理；有未提交改动或未合入提交的工作区不删。

跨会话长期并行时，改用宿主的多会话工作树（Claude 的 `claude -w <name>` 或 `/batch`），把合并单位提升为 PR。

## 复核与 verdict

VERIFY 只是一条秒级命令时，worker 自跑加主 Agent 抽查证据即可。行为改动、跨域影响、公共接口、配置或迁移，派独立复核：只读、不改文件，返回 `verdict`（pass / fail / blocked）、逐条 `findings`（文件:行号 + 证据）和实际跑过的 `evidence`。

复核尽量与实施单元使用不同模型或思考档位；同模型同档位存在共因盲区，无法分离时在汇报中注明。

head 变化后先比补丁再判断 verdict 是否失效：`git diff <base>...<head> | git patch-id --stable` 相同则原 verdict 仍有效，只需补跑验收命令；不同则回到未验状态，重新复核。不用旧 SHA 上的绿状态顶替。

## gap 不算 pass

brief 点名的证据缺任一项记 gap：不进 pass，重派一次补证；仍然缺失就按 gap 记录，不写成通过。

## 停止条件

同一 unit 连续 2 次失败挂起等人工，不自动重试；单 unit 超过 TIMEBOX 终止并保留已有进展。强推共享分支、删数据、对外发布等不可逆操作，无论是否在 brief 范围内，都停下来问。

## 汇报

按树汇报而不是按线性清单：每个 unit 的 verdict、所在层、改动文件、合并结果、blocked 原因和 gap。数字来自各 unit 报告与实际验证，不靠叙述。汇合记录写进项目现有任务状态；没有任务系统时写在回复和必要报告中，不新建平行清单。
